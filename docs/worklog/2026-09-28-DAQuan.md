## 1. Deploy lên Railway (bản v1)

- **Yêu cầu:** project tên DriveGuard, Docker multi-stage cho nhẹ, bản v1.
- **Cách build:** anh chọn **build image trên máy rồi push lên Docker Hub**, không để Railway build (`railway up` bị từ chối). Railway kéo image `docker.io/quanpk07/driveguard:v1` về chạy.
- **[Dockerfile.railway](../../Dockerfile.railway)** gồm 3 stage:
  1. Node build dashboard, với `VITE_API_URL=""` để gọi API cùng domain.
  2. Venv Python chỉ có FastAPI, JWT và PyYAML. Không có OpenCV, MediaPipe hay onnxruntime, vì server không chạy model.
  3. Runtime `python:3.12-slim`.
- [deploy/railway_app.py](../../deploy/railway_app.py) phục vụ API và frontend trên cùng một domain, không sửa logic backend.
- **Railway:**
  - Volume `/app/data` để giữ SQLite khi redeploy.
  - Biến môi trường: `DG_JWT_SECRET` (chuỗi ngẫu nhiên), `DG_CORS_ORIGINS`, `APP_VERSION`.
  - Domain `driveguard-production-6b83.up.railway.app`.
- **Dockerfile gốc** ở thư mục gốc (template khoá học) giữ nguyên.
- **Đo trên Railway** (1 giờ demo): CPU < 0,01 vCPU, RAM trung bình 20 MB, cao nhất 78 MB, p50 latency 5 ms. Vậy 0,5 vCPU và 256–512 MB RAM là đủ. Khi số xe tăng, SQLite (chỉ một luồng ghi) sẽ là giới hạn đầu tiên.

## 2. Tài khoản và thiết bị trên server

- **Tài khoản ở máy không có trên server.** Các tài khoản trong `data/accounts_2026-09-28.txt` nằm trong SQLite ở máy. Server có database riêng (ban đầu trống), vì `data/` cố ý không đưa vào image.
- **Cách tạo:** dùng `railway ssh -- python -m backend.manage ...`. Muốn chạy được thì phải tạo SSH key (`ssh-keygen`) rồi `railway ssh keys add`.
- **Đã tạo:**
  - Admin `admin`.
  - Tài xế `driver` (`drv-001`).
  - Thiết bị `cam-001` (`drv-001`). Device key chỉ hiện một lần, không ghi ở đây.
- **Cần làm:** mật khẩu đang dùng là mật khẩu demo dễ đoán. Server public nên phải đổi trước khi cho người khác dùng. Backend chưa có lệnh đổi mật khẩu, nên phải xoá user rồi tạo lại.
- **Chưa có:** dashboard chưa có màn hình tạo tài khoản. Backend đã có `POST /api/v1/users` nhưng chưa có giao diện gọi tới.

## 3. Camera ở máy, HUD trên web

- **Vấn đề:** HUD trên web gọi `http://127.0.0.1:8765` của edge agent nhưng bị chặn. Lý do là HUD server chỉ chấp nhận origin `localhost:5173`.
- **Sửa:**
  - Thêm cờ `--hud-origin <url>`, có thể lặp nhiều lần ([edge_agent/main.py](../../edge_agent/main.py)).
  - HUD server trả thêm header `Access-Control-Allow-Private-Network` để Chrome cho phép trang public gọi vào `127.0.0.1` ([server.py](../../edge_agent/hud/server.py)).
  - Mặc định vẫn giữ nguyên. Có thêm 1 test.
- **Giới hạn:** HUD trên web chỉ đọc được edge agent **trên cùng máy** đang mở trình duyệt.

## 4. Gói cài đặt cho người khác (`packaging/edge`)

- **Nội dung gói:**
  - `install.sh` / `run.sh` cho macOS và Linux; `install.ps1` / `run.ps1` cho Windows.
  - `edge.env` để điền device ID và device key.
  - [README.md](../../packaging/edge/README.md) bằng tiếng Việt cho người dùng cuối.
- **Build:** `packaging/edge/build_bundle.sh v1` tạo `dist/driveguard-edge-v1.zip` (14 MB), gồm edge agent, config và 3 model pretrained.
- **Đã thử trên Mac:** cài từ zip vào thư mục sạch, chạy bằng video mẫu với một backend tạm. Device key được chấp nhận, HUD server trả đúng CORS và header Private Network.
- **Chưa thử:** Windows, Linux, webcam thật.
- **Cần lưu ý:** YOLOv8n theo giấy phép AGPL-3.0. Nếu phát hành rộng rãi thì phải công khai mã nguồn theo giấy phép này.

## 5. M8: chạy hoàn toàn trên trình duyệt (`#/live`)

Anh chọn hướng "người khác chỉ cần cho phép camera là chạy". Logic khối 7–12 **chạy lại code Python qua Pyodide** thay vì viết lại bằng TypeScript, để chỉ có một nguồn logic.

### Kiến trúc

| Khối | Trên trình duyệt | Ghi chú |
|---|---|---|
| 1 Camera | `getUserMedia` | Cần HTTPS (Railway đã có) |
| 2 Tiền xử lý | Canvas: thu nhỏ về `target_width`; đo độ lệch kênh màu (IR) và độ sáng vùng mặt | **Không có CLAHE**. JS chỉ đo số thô, ngưỡng vẫn so trong Python |
| 3 MediaPipe | MediaPipe Tasks JS, **cùng file** `face_landmarker.task` | GPU, lỗi thì chuyển sang CPU |
| 4 YOLO | onnxruntime-web trong Web Worker, **cùng file** `yolov8n.onnx`, 5 lần/giây | Giải mã và NMS vẫn do Python (`decode_yolov8`) làm |
| 5 Eye state | `source: blendshape` (eyeBlink của MediaPipe) | Trình duyệt không có bộ phân loại ảnh mắt. Trên NITYMED AUC 0,986 so với CNN 0,881; riêng lúc đeo kính thì CNN tốt hơn |
| 6–12 | **Code Python của thiết bị**, chạy bằng Pyodide qua [edge_agent/web/bridge.py](../../edge_agent/web/bridge.py) | OpenCV `solvePnP` và NMS chạy được trong WebAssembly |
| 13 HUD | Dùng lại nguyên `HudScreen` / `HudView` (âm thanh, nút báo sai) | HUD nhận trạng thái từ một nguồn tuỳ chọn (`HudSource`) |
| 14 Gửi sự kiện | `POST /api/v1/web/events` bằng token đăng nhập | Thiết bị là `web-<username>`, sự kiện gắn vào `driver_id` của chính người đó. Chế độ "Dùng thử" không gửi gì đi |

- **Khối 3:** `landmarks.py` giờ import `mediapipe` bên trong detector thay vì ở đầu file, để các khối 5 và 6 load được mà không cần gói Python đó. Logic không đổi.
- **Backend:**
  - `store_batch` / `read_batch` được tách ra để endpoint thiết bị và endpoint web dùng chung.
  - Thêm `GET /api/v1/web/thresholds` để trình duyệt lấy ngưỡng đã được kỹ sư tinh chỉnh.
- **Trang `#/live`:**
  - Có cam kết quyền riêng tư, đăng nhập hoặc "Dùng thử không lưu", chọn tình huống xe (3 kịch bản CAN), và tiến trình tải model.
  - Chạy thì hiện HUD kèm khung camera nhỏ (EAR, yaw/pitch, FPS, thời gian YOLO). Ở L3, khung này thu lại thành nút "Dừng camera".

## 8. Hỏi đáp trong buổi (tóm tắt)

- **Kịch bản kích hoạt L1–L3:**
  - L3: nhắm chặt mắt ≥ 1,5 s khi xe đang chạy.
  - L2: nhìn lệch ≥ 2 s (1,5 s khi > 80 km/h), dùng điện thoại, mất mặt ≥ 3 s, hoặc drowsy_score ≥ 70.
  - L1: drowsy_score ≥ 40.
  - Kịch bản `highway_night` nhân điểm buồn ngủ lên 1,44 lần nên dễ demo L1/L2 hơn.
- **Cấu hình host:** xem mục 1. Thiết bị trên xe: đo được 152 FPS trên Apple M5. Ước lượng (chưa đo) máy ARM 4 nhân khoảng Pi 5 với 2–4 GB RAM là đủ 15 FPS.
